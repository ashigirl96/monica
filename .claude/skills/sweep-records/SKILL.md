記録は書いた時点の判断と事実で、古くなると参照ごと読み手のノイズになる。この skill は記録を消し、記録を指す参照をすべて片付ける。参照の中には、まだ誰かが使っている中身への案内が混ざっているので、消す前にそれを読み手の側へ移す。

対象は引数が名指す置き場（`adr`・`research`）で、無ければ両方。`CLAUDE.md` と `docs/agents/` は skill の読み方を決める file で、ユーザーが自分で直すので、そのまま残す。

## 1. 読み手を全部挙げる

```bash
git grep -nE 'ADR-[0-9]{4}|docs/adr|docs/research'
```

対象の置き場の中の行と、残す file の行を除き、残りの行を 1 行ずつ次の 4 種類に分ける。すべての行に種類が付いたら終わり。

- **データ**: code・テスト・設定が、置き場の中の file を読んでいる（例: テストが fixture の JSON を読む）。消すと壊れる。
- **案内**: skill や規則が「詳しくは X」「X の確かめをやり直す」と、記録の中身を読ませている。読み手はその中身を使って作業する。
- **括弧書き**: `（ADR-0015）`・`（ADR-0016・0018）`・`(ADR-0040)` のように、理由の出典を添えただけの括弧。外しても文の意味は変わらない。
- **文中の参照**: 文の意味が記録の番号や名前に頼っている（「予定の決まりは ADR-0016 にある」「結論は ADR-0013」）。

## 2. 案内の中身をユーザーに見せる

案内があれば、案内先の記録を読み、読み手が使う部分（順番、確認の項目、決まり）と、捨てる部分（調べ方、経緯、計測値）を分ける。分けた結果を、案内ごとに「移す中身・移し先・捨てる中身」の一覧にしてユーザーに見せ、了承を得る。移し先は案内を書いていた読み手そのもの（skill の該当の節、規則が名指す skill）にする。

案内が無ければこの手順は飛ばす。

## 3. 移す・消す・外す

1. **データ**は、読むテストの隣へ `git mv` で移し、読む側の path と、`.oxfmtrc.json` の `ignorePatterns` のような設定の path を直す。
2. **案内**は、了承を得た中身を移し先に「こうなれば成り立つ」の確認の形で書き、案内の文をその移し先を指す形に直す。
3. 置き場を `git rm -r` で消す。
4. **括弧書き**は、手順 1 の grep に当たった file のうち、残す file を除いたものに `perl .claude/skills/sweep-records/strip-citations.pl <file>…` を流して外す。引数無しで流すと、外し方の自己確認だけをする。
5. **文中の参照**は 1 行ずつ手で直す。記録が決めた中身を文に書くか、文ごと消す。番号だけを言うコメントで、テスト名や関数名と同じことしか言わないものは、行ごと消す。

## 4. 確かめる

- 手順 1 の grep が、残す file（`CLAUDE.md`・`docs/agents/`）にしか当たらない。
- `bunx oxlint`、`bunx oxfmt --check`、`bunx tsc --noEmit` が通る。worktree に `node_modules` が無ければ、先に `bun install --frozen-lockfile` を流す。`oxfmt` が設定の file を直せと言ったら `bunx oxfmt <file>` で整える。
- データを移したなら、それを読むテストが通る。Rust の file を直したなら `cargo fmt --all --check` が通る。

## 5. 報告する

次の 4 つを書く。

- 消した記録の本数。
- 移したもの（データと案内の中身）とその移し先。
- 捨てた中身。読み手から案内が消えたものは、読み手の名前を添える。
- 残した参照（`CLAUDE.md`・`docs/agents/` の中の、もう無い置き場への言及）。
