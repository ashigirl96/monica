これは `/teach-with-artifact` の指示で、この会話の残りすべてに効く。質問への答えを 1 枚の解説 artifact に育てる。追加の質問が来るたびに、答えをページに取り込み、節を前提のトポロジカル順に組み直す。

質問: $ARGUMENTS

## 1. 事実を集める

答えの材料は一次情報から取る: コード（`path:line`）、実際に打ったコマンドの出力、repo の docs。

- 動いている環境で確かめられることは、コマンドで確かめて出力をページに載せる。実演は外部に副作用の出ない形にする（例: proxy の挙動は存在しない port に向けて見る）。副作用が出たら、報告にそう書く。
- 読んだだけで動かしていない部分は、ページの中で「コードと docs から書いた、動かしていない」と明記する。
- token・鍵・home の path は伏せて載せる。

完了条件: ページに載せる主張がすべて、`path:line`・コマンド出力・docs のどれかに辿れる。

## 2. 最初の artifact を作る

最初の回答は、チャットで短く答えてから、同じ内容で artifact を公開する。ファイルは scratchpad に置き、以後ずっと同じ path で公開して URL を保つ。

見た目は [`style.css`](style.css) を土台にする。色の token（青緑の accent、図の正規経路・素通り・遮断に使う accent・warn・bad）、font、図・表・注記・目次の class がそろっている。

ページは前提の順に節を並べる:

- 各節の **前提**（読む前に分かっている必要がある節）を決め、前提が必ず上に来る順に並べる。
- 各節の見出しの上に段の名前を置く。段は内容に合わせて選ぶ。例: 基礎 → 組み立て（基礎を組み合わせた実際の仕組み）→ 弱点 → 対策 → 発展。
- 冒頭に、段の名前付きの目次を置く。
- 後の節は前の節を名前で指して積み上げる（「基礎 1 のとおり」）。前の節が後の節の内容を先取りしたら、その部分を後の節に移す。

## 3. 追加の質問を取り込む

追加の質問には、まずチャットで答える。そのあと聞かれなくても、答えをページに取り込んで公開し直す。

1. 新しい内容の前提を決め、その前提が揃った直後に置く。既存の節に収まるなら節の中に、収まらなければ新しい節にする。
2. ページ全体を見直す: 前提より上に来た節、先取りした記述、同じ意味の重複、目次とのずれ、古くなった相互参照（「次の節」など）を直す。
3. 節を並べ替えるときは、その前に今のファイルを `.v<版>.bak.html` として scratchpad に複製する。

完了条件: どの節も、前提がすべてその節より上にあり、目次が節の並びと一致している。

## 4. 報告する

公開のたびに、URL と、変わった節ごとに何を足し・移し・削ったかを並べる。並べ替えたときは、新しい順番と各節の前提を表にし、バックアップの絶対 path を書く。
