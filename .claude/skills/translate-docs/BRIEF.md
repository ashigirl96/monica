# 翻訳の指示

**元ファイル** の英語の Markdown を自然な日本語に訳し、**出力** に書く。ほかのファイルは書かない。

## 形

- **元の 1 行に出力の 1 行を当てる。** 行数はぴったり合わせる。後で script が見出しを行番号で対応づけるため。空行は空行のままにする。
- Markdown の構造はそのまま保つ: 見出し、リスト、表、リンク、画像、front matter のキー、HTML タグ。
- **翻訳ルート** の中の別の `.md` へのリンクは、その隣の `.ja.md` を指すよう書き換える（`./02-mode.md#run` → `./02-mode.ja.md#run`）。`#anchor` の部分は英語のまま残す。翻訳ルートの外へのリンク、URL、画像のパスはそのままにする。

## 地の文

- 全体を常体（だ・である調）で書く。簡潔な技術文書の文体にする。
- 一般的な概念は、自然な日本語の言葉があればカタカナより日本語の言葉を使う。
- 次は英語のまま残す: インラインコード、コマンド、ファイルパス、設定キー、コード中の名前、製品名、skill・principle・playbook の名前。次の道具の名詞も英語のまま残す: skill、playbook、subagent、worktree、branch、commit、PR、merge。
- 地の文でコード中の名前（変数・関数・クラス）を出すときは、`元の名前`（その文脈での意味や役割）と書く。例: `scanner`（対象を広く調べる処理）。カタカナの読みは注釈にならない。注釈はファイルの中で初めて出す箇所に付ける。
- 名前そのものを指す必要がない箇所は、日本語の説明で呼ぶ。
- コマンド・設定キー・ファイル名・製品名は正確な表記のまま書き、初めて出す箇所に用途を日本語で添える。
- 注釈は地の文に付ける。見出し・コード・コマンド・引用・prompt の例の中には入れない。注釈にリンクを入れない。
- 画像の alt テキストは訳す。注釈のほかは足さない、削らない、絵文字を使わない。
- 書き終えたら、上の英語のまま残す語のほかに、注釈のない英単語が地の文に残っていないか見直す。

## コードフェンス

- **コード**（shell、TypeScript、JSON、YAML、mermaid など、`text` 以外の言語タグ）は 1 バイトも変えない。
- **prompt の例**（ユーザーが agent に打ち込む文を入れたフェンス。たいてい `text` のタグが付き、slash command で始まることが多い）は訳す。人が agent に打ち込むように書く: 短く、くだけた頼み方（「〜して」）にする。次は英語のまま残す:
  - slash command そのもの（`/poteto-mode`、`/how`）。行のどこにあっても残す。
  - placeholder（`<base>`、`<app>`）、フラグ（`--json`）、パス、数、識別子。
  - skill・principle・playbook を名指す句（`subtract before you add`、`autopilot-full`）。

  `/poteto-mode users get two notifications after a retry. repro first, then fix and verify.`
  → `/poteto-mode リトライの後に通知が 2 通届く。先に再現して、それから直して確かめて。`

  command だけの行（`/setup-pstack`）はそのまま残す。
- 地の文が prompt の例の句を引くとき（「repro first」）は、例で使ったのと同じ日本語で引く（「先に再現して」）。

## 報告

出力のパスと、元ファイルと出力の行数を返す。
